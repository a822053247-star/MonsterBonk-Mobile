## 2. 已完成：P2 收尾，只接入两类敌人外观

目标：让当前战斗中的主角与基础敌人在像素风格上更统一，继续验证手机横屏辨识度。此轮不新增敌人种类或属性，不改数值与生成规则。

|任务|实施范围|验收标准|
|---|---|---|
|素材映射|建议 `normal` 使用 `grass-monster.png`，`fast` 使用 `runner-bug.png`；`tank` 保留占位|只替换外观，不从图片颜色推定元素属性，也不改变敌人 kind|
|批量显示|沿用 `CombatView` 的实例渲染思路，按贴图分少量批次，使用朝向相机的平面|不为每次生成/死亡创建独立材质和纹理；不丢失原有批次容量限制|
|比例与地面关系|复用像素纹理准备方法、NearestFilter、脚底锚点和等比显示|普通怪和快速怪轮廓可辨，透明边不出现方框，前景遮挡正常|
|原效果兼容|保留出生预警、血条、受击反馈、锁定圈和脚影|替换身体后，没有漂浮的旧眼睛/角/护甲；坦克占位显示不受影响|
|回退与保护|保留原几何显示，单类贴图缺失时局部回退|移动、速度、碰撞、生命、伤害、经验和自动攻击结果与旧显示一致|

本轮完成条件：构建、已有回归及必要的显示专项测试通过；提供 844×390、568×320 两种实际运行截图；报告纹理数量、批次变化和未做的真机验证。不要顺带开发商店、掉落事件、祭坛或地图交互。

## 3. P3：分三轮建立正式成长循环

### P3-A：单兽开局、等级槽位、金币、波次骨架

1. 正式流程开局只有一只主控。第二、第三槽分别在 Lv.2、Lv.4 解锁；解锁只获得空槽，不自动赠送幻兽。保留“三兽技术原型”作为开发回归入口。
2. 区分“首版最大容量 3”“已解锁槽位数”“实际成员数”，未来四槽扩展保留，但正式 UI 不开放第四槽。
3. 建立单局金币状态。普通敌人死亡时有 20% 概率增加 1 金币；每个死亡只结算一次。建议 P3 直接入账，不另做金币落地与磁吸动画。
4. 建立独立波次计时：每波 80 秒，仅战斗推进；暂停、升级、商店、后台均冻结。波末奖励 12 金币并进入波间界面；点击“下一波”才能继续。
5. 不更改现有经验曲线。该轮波间界面可暂只显示信息与继续按钮，明确是开发中的商店骨架，不宣称完整商店已经完成。

验收重点：等级跳升时准确解锁；空槽不参与跟随和攻击；金币不重复发放；波末与升级同时发生时只进入一个界面；重开清空本局经济、波次和解锁状态。正式六波配置可以预留，此轮不把计时结束当作正式通关验收。

### P3-B：招募、满槽替换、一次刷新

- 招募普通幻兽 12 金币，支持同物种重复。未满“已解锁槽位”时直接加入；已满时在商店内选择替换或取消，没有候补区、背包或溢出槽位。
- 替换确认后才扣款并生成新实例；取消、重复点击或过期卡牌不会扣款。成员变动只发生在暂停的商店状态。
- 每次商店最多付费刷新一次，价格 2 金币；钱不足不执行，下一家商店重新获得一次刷新资格。
- 选项生成检查实际效果：不提供针对不存在成员的升级、不指向锁定槽、不重复出售已经失效的卡。不生成与当前同物种同状态完全等价的无意义替换。
- 当确实没有可购买项时显示原因并保留“下一波”，不伪造可用商品、不强制消费、不临时发放额外金币。

验收重点：扣款与成员变动是一次完整事务；满槽替换、同种重复、无钱刷新、快速连点、取消与重开均有测试。购物后新成员正常跟随和自动攻击。

### P3-C：阶级 II 升级与更换主控

- I → II 花费 8 金币，强化效果通过统一属性入口结算，具体增幅作为待定配置，实施前写入平衡表。
- 商店可更换主控；共享生命的当前值与上限不因切换而重置或变相回血。HUD 名字、像素图、识别环、拾取点、相机跟随及攻击来源应一起切换。
- 保留成员身份及各自冷却、阶级和进化状态；更换主控不重新创建全队，也不重复应用旧强化。
- 阶级 III 价格保持 14 金币，但涉及基础进化，归 P4 完成。机制未实现时不出售“扣钱但无进化效果”的 III 阶商品。

验收重点：受伤后换主控生命值完全保留；切回旧主控不叠加加成；升级立即改变实际攻击；主控贴图缺失时仍有可辨认的回退外观。

### P3 的状态边界与技术要求

建议状态路径：`战斗 → 波末结算 → 待处理升级选择 → 商店 → 下一波`；死亡优先于继续，所有结算都必须幂等。商店购买不得触发战斗推进。

建议波末清退尚存敌人和投射物，不按击杀发奖；保留未拾取经验、已获得奖励、队伍、阶级和共享生命。该政策在 P3-A 落地前记录为明确配置，后续区域系统沿用。**不能调用整局 `Combat.reset()` 来结束一波**，以免重置经验、技能和生命。

复用 `Game / Combat / Progression / PartySystem`，按实际复杂度增加经济、波次和商店模块，不为了类名拆散现有工程。`PartySystem` 增加受约束的招募、替换与选主控接口；UI 不直接修改 roster 或金币。

现有属性缓存只比较旧强化对象。阶级、进化、成员构成发生变化后，必须使缓存失效；建议引入成员/队伍修订号，避免“界面显示升级，实际攻击未变化”。

## 4. P4：让三种构筑真正不同

按“统一结算 → 基础物种机制 → 羁绊 → III 阶基础进化”逐项落地，不同时引入探索奖励。

|内容|正式规则与验收|
|---|---|
|克制|火克草、草克水、水克火；1.25 / 0.85 / 1.0 经统一伤害入口结算，敌人元素来自数据配置，不来自图片颜色|
|属性羁绊|2 同属性伤害 +10%，3 同属性提升为 +18%，不叠成 +28%|
|种族羁绊|2 同种族攻速 +8%；同属性与同种族可同时生效；3 同种族不按多个配对重复增加|
|火花弹|落实范围输出；同次爆炸不能对同一敌人重复结算；伤害/半径另列平衡配置|
|水泡|落实减速控制；持续时间、减速上限与刷新规则明确，禁止无边界叠加|
|叶刃|落实穿透输出；同枚叶刃对同一目标的重复命中有明确定义和限制|
|阶级 III|商店升级触发基础进化，既改变贴图也改变攻击机制；材料未齐时的开发占位不算正式美术验收|

测试必须覆盖伤害公式、攻速换算、缓存更新、同种重复、移除成员后羁绊消失、暂停/重开和有界效果池。此阶段仍不开放完全体材料或闪光变异来源。

## 5. P5–P7：在基础循环稳定后扩展

|阶段|实施顺序|通过标准|
|---|---|---|
|P5 区域与警戒|先连通区域与通道，再独立警戒、怪物/追踪物边界、撤离资源处理|三种区域可达；警戒 0–100 独立保存与慢回落，跨区不清零；未拾取事件资源按撤离政策放弃，已获奖励保留；所有区域仍有当前波次基础压力|
|P6 探索奖励|先普通蛋自动孵化，再满槽替换/放弃，再祭坛，最后闪光蛋与完全体材料|触碰交互，无额外战斗按钮和背包；祭坛同时有增益与代价；闪光仅来自稀有蛋；完全体材料只来自探索，来源可测试追踪|
|P7 完整挑战|六波及 Boss、数值与构筑验证、性能优化、真机与发布准备|完成 6×80 秒正式挑战；明确第六波 Boss 和胜利条件；验证常驻区域、可选探索、混合队伍与同种队伍的可行性；记录真实设备帧率、内存和后台恢复|

P5 必须遵循的警戒增加：普通蛋 +15、宝箱 +20、闪光蛋 +40、完全体材料 +45、祭坛 +25；0–29 平静、30–69 警戒、70–100 高危。衰减速度、跨区追击距离/时间和事件密度尚未定版，需配置化调试。

敌人当前仍有全量两两避让。**提高敌人上限或同时激活更多区域前**，先换为局部空间查询并设置实体/投射物/粒子总预算；不能等性能退化后再用减小摇杆响应补救。远区可低频维护压力预算，但不能因此让跨区变成清空压力的漏洞。

P7 要分别记录战斗时间和包含商店的整局时间，用实测校验 8–12 分钟目标。第六波 Boss 出场时间与胜利条件在该阶段实现前固定，不把 Boss 当成另加的第七波。平衡测试提供多组种子与玩法记录；不能仅凭一局脚本胜利声称所有构筑平衡。

## 7. 尚待定版的设计参数

下列内容不是遗漏的正式规则，不应在代码中伪装成已确认设定：

- 初始金币、初始可选物种、每店卡牌数量及刷新池权重。建议首次先固定焰绒开局与 0 金币，避免同时引入选角界面；此项属于可调整建议。
- I → II 的数值增幅、III 阶三物种的具体机制和数值、基础攻击的范围/减速/穿透参数。
- 现有升级卡加成是全队生效还是部分归属主控。迁移期间保留现状：基础攻击强化参与全员计算，旧环绕/冲击波围绕主控；改归属前先明确 UI 和数据规则。
- 玩家等级、幻兽阶级、属性羁绊的加成计算顺序；进化或换主控是否影响生命上限。正式换主控必须保持共享生命，不可借此恢复或提高生命。
- 波末实体清退政策、敌人元素配置、Boss 胜利条件与区域警戒回落参数。

实施某一轮前，只处理影响该轮的参数；未来阶段未定不阻塞当前可独立交付的任务。所有新数值写入集中配置并标明调试性质，不散落在 UI 或渲染代码。

## 8. 每轮实施与交付约定

1. 检查 Git、确认真实实现、保护已有未提交内容；必要时使用独立检查点和仓库外 bundle，不直接 reset/clean 用户目录。
2. 写清本轮目标、允许修改的模块及不实施的阶段。保留原地图、素材、加载路径与有效回归入口，避免无意义重构。
3. 只添加覆盖新风险的测试，运行构建和既有回归；实际输出通过/失败/跳过数量。纯文档更新不要求重跑整套游戏测试。
4. 涉及显示或界面时提供实际截图，至少检查 844×390、568×320 与安全区；真机与桌面模拟分开记录。
5. 更新验收记录和 README 当前状态，恢复旧测试覆盖的历史截图，用新文件名保存本轮证据；最后列明已完成、未验证和下一轮任务，然后停止。

执行时只保留一个摇杆、自动攻击、主控唯一承伤和无背包原则。任何新玩法需求先对照 GDD；素材存在不等于应当提前开发其功能。

## 9. 下一轮可直接使用的任务说明

> 仅实施 P3-A：在现有工程加入正式单兽开局、Lv.2/Lv.4 空槽解锁、单局金币与 80 秒波次骨架。解锁不赠送幻兽；普通敌人击杀按 20% 概率 +1 金币，波末 +12 金币并暂停，点击下一波恢复。保留三兽技术回归入口、当前像素显示与经验曲线。先按本计划明确初始金币、开局物种和波末清退政策，再实现波间信息界面；不开发招募、刷新、阶级升级、换主控、随机地图或进化，不把波次骨架宣称为完整六波通关。保护未提交工作，运行构建、回归与必要的状态/结算测试，提供横屏截图，完成后停止。
