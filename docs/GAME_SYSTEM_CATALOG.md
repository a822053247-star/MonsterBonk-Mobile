## 0. 给 ChatGPT 和 Codex 的阅读说明（优先阅读）

**项目一句话：** 《幻兽幸存者》（MonsterBonk-Mobile）是 TypeScript + Vite + Three.js 的移动端 2.5D 幸存者游戏，现有两种正式战斗入口：**闯关挑战**（单幻兽、单虚拟摇杆、自动攻击、三武器构筑、升级融合、六波通关）与**无尽挑战**（无限地图、循环六波、第五波旗帜大波/商店、第六波重复 Boss、轮次难度和特殊规则）。历史试炼继续隔离；死亡仍是真实失败。

**严格区分状态：**

- `IMPLEMENTED`：从所列代码中已验证存在；数值以对应源码为准。
- `DESIGN_LOCKED`：已确认的设计方向/约束，**尚不意味着代码已实现或已授权开发**；代码任务必须单独指定范围。
- `PROPOSED`：设计讨论提出的候选方案，**尚未在本基线代码中实现**；数值为原型目标。
- `OPEN`：仍需决策，不得擅自按已确认功能实现。
- `DEPRECATED/LEGACY`：旧模式/历史规则，不应意外带入正式模式。

**每次开始新任务：** ① 从仓库根目录 [AGENTS.md](../AGENTS.md) 按任务定位，新增内容参考 [接入指南](CONTENT_DEVELOPMENT.md) 对应章节；② 只读取本档案任务相关的条目和源码，涉及玩法方向时核对第 0 章，不默认通读第 0～3 章；③ 核对 Git 当前 HEAD 与 `baseline_commit`；④ 只改明确要求的功能，不把 `DESIGN_LOCKED` / `PROPOSED` 全量实现；⑤ 更新涉及条目的状态、数值、对应测试与更新记录。若文档和代码冲突，先报告差异，以代码实测为准。

**项目原则：** 维持单摇杆自动攻击；死亡是真实失败；技能是稳定成长、遗物是稀有规则改变；让风险带来有意义的选择，但不搞真实金钱赌博或付费随机抽取；优先利用代码特效与现有贴图，只用 ChatGPT 生成极少数关键美术帧。

**角色与近战表现规范（`DESIGN_LOCKED`）：** 玩家形象的视觉基准是**四足、贴地爬行、可爱的小火狐焰绒**，不是站立的人形战士。正式近战首先采用**自动触发的元素横扫 / 狐爪弧光**，其真实命中为扇形范围判定；角色**不手持刀、锤、长枪**。可选的**漂浮魔法武器**只作为高级遗物、终极进化或召唤能力的表现，且不得遮挡受击预警。动画首选程序化旋转/缩放/弧形几何，不要提前要求大量图片逐帧。其他两只现有幻兽也须保持其原有非人形身体比例，不因新增武器变成人形。

**条目 ID 规则：** 正式已有内容使用代码中原始 ID（如 `spark`、`split-on-hit`）；提案使用 `draft-` 前缀（如 `draft-flame-sweep`）。未来实现时，应决定是否移除前缀并维护迁移表，避免覆盖已有存档或测试标识。名称、类型、效果、获得方式、联动/限制、状态、实现位置是最低必填字段。

### 0.1 Codex 快速定位与冲突优先级

1. **实施现有规则 / 排查 bug**：以当前仓库源码和运行测试为准；本档案只帮助找位置。
2. **实施未来功能**：以明确的本次开发任务为准；可参考本档案的 `DESIGN_LOCKED` 原则与对应 `PROPOSED` 条目；`OPEN` 必须先确定具体行为，不自行猜。
3. **旧 GDD、历史报告与本档案冲突时**：已实现事实由代码决定；新方向由明确的新设计决定，禁止悄悄改动历史模式。
4. **产出代码前**：列出本次涉及的 ID、现有文件、拟增加的数据字段、事件顺序、原有回归测试与新增验收测试；不改动无关模块。
5. **产出代码后**：更新本文件相应条目的状态、最终数值、测试路径、提交号；禁止只更新策划文档而不运行测试。

**已锁定的游戏分类**：`weapon`（独立自动攻击，最多 3 槽）≠ `skill`（升级成长或融合触发）≠ `fusion`（武器和技能满足条件时自动派生）≠ `relic`（稀有规则改变，基线已有 6 件）≠ `evolution`（互斥强化）≠ `curse/contract`（未来风险交换）。**遗物不替代技能或武器。**

**美术制作约束**：Codex 先以色块、已有纹理、InstancedMesh、几何弧光完成可玩的核心循环；ChatGPT 美术集中在经验证需要的**角色关键帧、代表性爆发帧、统一图标图集**。资源未落库前不得写死文件名或把概念图视为正式资产。

| 波次 | 战斗时长 | 背景供给（只/秒，未受拥挤/事件限速时） | 调度活跃上限（含预警/精英/Boss） | 特殊事件 |

### 1.1.1 波间渲染开销修订（`IMPLEMENTED`，1.6.6）

针对第一波结束后掉帧的反馈，移除已复现的波间重复工作：原流程在固定步补算及显示帧反复写入整套 HUD，一次模拟慢帧可调用 9 次；现只在进入波间、倒计时整数变化及退出时更新。输入关闭、角色停步和战斗表现清理只在进入波间执行一次；已清空的战斗特效不再逐帧更新，场景和角色仍由正常动画循环绘制。保留 3.5 秒休息、经验回收/连续升级及第五波后商店规则。

验证：`tests/wave-boundary-performance.spec.ts` 覆盖空经验、96 槽经验结算与连续升级、慢帧补算及真实 RAF 自动进入第二波；同一补算场景 HUD 刷新从 9 次降至 0 次，整段倒计时只按 3/2/1 更新。相关模型和六波 UI 回归共 30 项通过，新增真实循环验证两项通过，生产构建通过。这证明重复工作已移除，不代表已经测得用户设备的帧率或排除其他卡顿来源。

**持续卡住反馈（历史记录，旧第一波休息路径已由 1.6.7 替换）：** 用户随后提供截图，第一波完成界面显示“1 秒后进入第 2 波”，反馈仍无法移动。追加完整首波战斗、火花/飞叶融合构筑和升级结算，经过真实 RAF 波间倒计时后，验证键盘及摇杆能实际产生位移；固定地图和种子随机地图在 Chromium / WebKit 共四项通过，未复现该持续卡住。1.6.7 按用户提出的新规则移除这段第一波休息流程，不将其表述为已找到旧卡住问题的根因；上述休息期性能优化继续作用于第二至第五波结束的波间。

### 1.1.2 生存波无缝衔接（`IMPLEMENTED`，1.7.1；始于 1.6.7）

第一波 65 秒计时结束后，立即切换为第二波的 70 秒计时及刷怪计划，不进入“第 1 波完成”休息界面、不关闭/重置键盘或摇杆输入。第一波存活敌人沿用原对象、ID、当前位置、当前/最大血量及燃烧等状态继续战斗；不因切波死亡或结算击杀。场上经验球保留原地，继续正常拾取，不在这次边界强制回收；投射物、特效、玩家受击保护及遗物战斗状态延续。第一波 +35 金币奖励仍只发放一次，旧敌人在第二波被击杀后再正常发放其击杀奖励；第二波新增敌人与遗留敌人共用52活跃上限（1.9.0）。新一波首批刷怪仍采用原来的 1.2 秒准备时间。

**1.7.1 扩展：** 第一至第四波到时全部直接进入下一波，不再显示这些波次的完成休息界面，不强制清场/集中回收经验，不关闭或重置输入。每波奖励仍只结算一次；存活怪物和待触发爆孢预警、燃烧、遗物时钟、弹体/特效继续存在，共用下一波的敌人总上限。第四波未击杀的精英保留对象、血量、震地蓄力、冷却及敌方弹体状态进入第五波，不能因 encounter 换波重置而丢失攻击逻辑。第五波结束后才清场、回收经验，休息 3.5 秒进入唯一商店；第六波最终 Boss 规则不变。正常拾取经验触发的三选一仍会暂停。

原因与边界：原来只有第一波无缝；第二波及之后仍主动回收经验、清场并进入休息。该主动清场/停步路径与用户“第二波完成后敌人消失”的反馈一致，并非通过补充敌人图片修复。敌人像素图集在开局 `EnemyPixelView.enableBasics` 已请求全部种类；新增草原音乐预加载以避免第三波才首次请求，普通波次推进不等待资源下载。

实现：`src/run-flow.ts::resolveBoundary/prepare`、`src/enemy-challenge.ts::beginWave`、`src/game.ts::syncRunPhase`。验收：`tests/run-flow.spec.ts` 覆盖四次连续边界、敌人/血量/燃烧/弹体/经验球/保护延续、精英蓄力保留、奖励不重复及第五波商店；`tests/wave-boundary-performance.spec.ts` 在阻断音乐资源时以真实帧回调验证第二波 1/10 倍及第三/四波 10 倍下按住键盘/摇杆仍移动，保留固定/随机地图完整第一波和第五波休息回归。

验证结果：波次模型、六波 UI、持续输入、怪潮经济/预算、特殊成长与 Boss 行为在 Chromium / WebKit 共 94 项通过；`npm run build` 通过。

- **身体接触：** 仅正式六波，所有存活且已结束出生预警的敌人（除无伤害携宝兽）使用相对位移线段碰撞，覆盖角色移动/冲刺与敌人移动；身体是否危险不再取决于其蓄力、恢复、硬直或攻击状态。接触半径为敌人碰撞半径 +0.3；普通岩甲保持原 +0.17 的紧贴接触范围。障碍遮挡有效。贴进预警怪身体会受伤，站在身体外仍可按预警躲避特殊攻击。
- **结算：** 每帧身体接触取最高一次伤害，与现有攻击伤害比较后只取一次最大值；各敌人伤害/怪潮低伤数值不变。纯身体接触后保护 0.45 秒，持续贴身/穿过敌群可再次扣血；特殊攻击/弹幕/爆炸仍保留 0.85 秒保护。共用同一个保护时钟，避免同帧叠加秒杀。玩家脱离危险、出生预警、暂停/死亡和原有失败优先级保持有效，历史接触模式沿用原实现。
- **受击表现：** 三只像素主角都新增约 0.25 秒的横向撑开/纵向压缩、短促摆动与轻微身体抖动、暖红闪色；保护期剩余时间用半透明闪烁提示。仅改变精灵本体，不移动真实位置、影子、控制输入或命中盒。每次渲染从原始比例重新计算，恢复后不残留缩放/偏移/旋转。原有受伤音效、屏幕边缘提示和血条继续使用实际伤害结果。

## 9. 交叉组合与事件协议（`PROPOSED`）

### 9.1 推荐统一战斗事件

| Event ID（草案） | 触发位置 | 携带字段建议 | 需要满足的安全规则 |
|---|---|---|---|
| `attack_fired` | 武器发动 | attackId、weaponSlot、origin、generation | 攻击复制不得自递归 |
| `damage_applied` | 真正造成伤害 | targetId、damage、sourceId、element、tags | 同一攻击/目标去重 |
| `status_applied` | 附加状态 | targetId、statusId、duration、sourceId | 重复叠加/刷新要确定性 |
| `enemy_killed` | 从存活到死亡的唯一状态变化 | targetId、killerSource、kind、generation | 一个敌人只结算一次死亡与 XP |
| `area_burst` | 范围伤害请求 | position、radius、damage、tags、generation | 每帧与传播深度双预算 |
| `melee_sweep` | 近战自动攻击的范围命中判断 | arc、range、attackId、sweepId | 同次挥砍同一目标最多一次伤害 |

建议所有伤害事件携带来源和 `generation`，避免殉爆晶核、荆棘遗嘱和回声骨骰联动产生无限递归。为了手机性能：允许将逻辑上多次的伤害合并成少量可见粒子；不可通过限流偷偷丢失必然伤害，必须在规则中定义如何截断/延迟事件。与现有固定时间步、确定性 RNG 和 `damageEnemy` 的联结由 Codex 在实际开发时评审。

### 9.2 触发顺序与上限（Codex 实现前必须明确）

1. **攻击创建**：快照武器、技能、遗物数值，生成独立的 `attackInstanceId`、`sourceId`、`generation=0` 和 `originType`。
2. **伤害应用**：统一命中检查，计算实际伤害，结算护甲/免疫后记录 `damage_applied`；同一攻击对同一目标不得因同帧重复判断再次命中（持续 AoE 另定义窗口）。
3. **死亡锁定**：HP 首次降为 0 时，唯一发出 `enemy_killed`，只结算一次击杀数、经验、金币、Boss 特殊逻辑。
4. **遗物派生**：从**有序事件队列**消费击杀/状态/范围事件，生成二级事件；新增标签 `no_retrigger_same_relic`、`copied_attack` 之类阻止回声和死亡自循环。
5. **预算溢出**：常规传播深度建议最多 2–3；每 tick 追加事件建议从 32 件起测。达到预算后采用**显式规则定义**（安全延后结算或受控截断），不得默默丢失基础伤害、Boss 击杀或经验奖励。
6. **表现层**：伤害逻辑与特效分离，允许将数十次真实命中合并为 1–3 次明显的爆炸演出；保证冲刺线、Boss 弹幕与爆孢死亡预警仍然清楚可见。

当前 `damageEnemy` 已为 3.3 / 3.4 六件遗物接入来源快照、唯一死亡、有序派生队列、复制计数与冷却，但尚非完整通用事件总线；本章通用事件 ID 仍是**实现契约草案**；1.8.0来源、就绪队列与跨元素实际规则以3.5为准。随机事件应沿用可注入 RNG，保证同种子和相同操作能够复现结果。

### 9.3 典型联动验证表

| 构筑名（设计昵称） | 构成 | 需要测试的边界 |
|---|---|---|
| 无尽火葬场 | 火花弹 + 命中分裂 + 殉爆晶核 + 怪潮号角 | 连锁深度、密集杂兵死亡去重、Boss 召唤物 |
| 泡影永动机 | 水泡弹 + 连锁弹射 + 泡泡孢子 + 回声符石 + 回声骨骰 | 不出现无限派生、24 弹池耗尽时表现 |

## 10. 面向 Codex 的实施与验收约定

### 10.1 版本顺序建议与当前进度

| 里程碑 | 最小变化 | 禁止搭车的范围 |
|---|---|---|
| P0 怪潮原型 | V6.1-A 已实现赤团成组与金币/经验分配；晶屑虫仍待开发 | 暂不引入全部 12 遗物 |
| P1 近战原型 | V6.1-B 已实现 `flame-sweep` 火焰横扫、扇形命中、三槽兼容与用户八帧图集 | 不做手持武器；不引入漂浮火刃及其他近战 |
| P2 遗物核心 | 六件触发遗物和专用队列/来源/攻击快照/冷却已实现（3.3 / 3.4） | 不同时重做商店经济与路线地图 |
| P3 风险循环 | 精英三选一、玻璃王冠、怪潮号角、死亡复盘 | 不做真钱/付费赌博 |
| P4 扩展与视觉 | 其余遗物、诅咒、命运事件、图鉴；批量关键美术 | 不大规模单图逐次调用生成 |

### 10.2 最低测试标准

- **构筑合法性：** 旧/新武器槽位、重复取得、等级、已失效遗物条件。
- **战斗正确性：** 单次死亡不重复掉落；多来源伤害可追踪；Boss 击杀与超时条件不变；玩家死亡高于通关。
- **事件终止：** 任意随机种子在事件限制范围内都能完成 tick，不能出现递归卡死。
- **兼容性：** 原三武器、五融合、六遗物、两进化、历史模式测试不回归。
- **移动端性能：** 24/36/48 敌人压力场景；高连锁峰值；中端真机持续 10–15 分钟；优先 30 FPS 基准、旗舰 60 FPS 目标；记录绘制调用和逻辑耗时。这些是**待验收目标**，不是已达成结果。
- **可理解性：** 死亡前应有警示；危险交易在确认前完整展示代价；玩家能够辨别攻击来源。

### 10.3 AI 生成美术约定

1. 主角是**四足爬行的小火狐**；基础近战必须是**元素横扫弧光**，不可直接改成人形持械动画。先使用**程序化几何弧光、爆炸圈、改色/缩放、现有图集**开发核心体验。
2. 只有可玩原型验证方向后，再批量生成**少数真正缺失的**角色关键帧、Boss 动作关键帧、融合高潮帧、统一遗物图标图集。尽量复用现有素材，单次出图要包含明确分格、尺寸、透明背景和导入规范。
3. 不要求 ChatGPT 每个攻击、每件遗物生成独立逐帧动画。Codex 负责动画状态机、UV/图集切分、淡入淡出、旋转缩放与资源复用。
4. 漂浮武器只用于获得相应稀有能力后的高级视觉；不常驻遮挡主角和敌方攻击预警。AI 图片提案不能等同于已存在的资源文件；只有真正放入仓库并接入加载器后，才能标注 `IMPLEMENTED`。
