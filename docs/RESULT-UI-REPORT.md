# 第四阶段：童话冒险战报

## 表现层改造

- 结算标题、胜负标识与操作按钮居中置于装饰框外；羊皮纸面板只承载动态成绩与最终构筑，避免文字挤到藤蔓、宝石和四角。
- 使用 `result/battle-report-panel.png`；胜利使用 `result/victory-crown.png` 和金色魔法氛围，失败使用 `result/defeat-badge.png` 和蓝绿色暗背景。
- 所有文字、数字、失败原因和构筑由 DOM 动态绘制；没有将任何文字写进图片，没有改动原素材。缺图显示 CSS 羊皮纸与原叶片图标。
- 成绩突出总用时/生存时间、击败数和经验；构筑列出武器等级、已学强化与等级、实际融合、道具及互斥进化。完整模式与历史模式均有构筑摘要。
- 常见横屏双列展示成绩与构筑；窄屏改为单列局部滚动，保留重试和返回菜单按钮，支持安全区。

## 数据与逻辑边界

- 保留原 Game.endRun 触发、胜负判定、RunFlow.finish、暂停/输入禁用、再次挑战和菜单导航。game.ts 中新增展示函数调用，更新失败提示文案，未改战斗或状态机分支。
- 总用时仍使用现有 `formatTime()`：正式六波含战斗和休整，标签明确为“总用时”；历史模式仍显示“生存时间”。面板进一步列出当前 run.combatElapsed 与 restElapsed，不混淆时间口径。
- 击败数读取 combat.kills，经验读取 combat.xp（累计已收集经验），金币与完成波数读取当前 RunFlow；不预设通关成绩。
- 生命耗尽和首领90秒超时显示真实失败原因。失败只展示本局实际成绩与获得的金币，不生成通关奖励、皇冠或胜利星级。
- 只有历史三波挑战继续显示其真实星级；正式六波不凭空添加星级。最终构筑直接读取当前 RunBuild、Progression 与融合结果。

## 验证

生产构建，以及 Chromium/WebKit 下的 result-art.spec.ts、run-flow-ui.spec.ts、challenge-ui.spec.ts。

最终结果：构建通过，16项针对性回归全部通过。保留既有 Three.js 大分包体积提示。

新增覆盖：实际首领死亡后的胜利、生命耗尽与首领超时、图标互斥、成绩与当前状态逐项一致、武器/强化/融合/道具/进化完整展示、无虚构奖励、568×320安全区、图片失败回退及重试/菜单。

预览：`artifacts/adventure-report-victory-chromium.png`、`artifacts/adventure-report-health-chromium.png`、`artifacts/adventure-report-timeout-chromium.png`。未运行全项目测试集。

## 文字安全区与精简修正

原面板整图拉伸会让装饰进入文字区域，现改为九宫格边框：边框与留白实际占据盒模型空间，正文只能位于内部。隐藏重复的结束小标题，波次摘要只保留波数和本局金币，去掉生命、剩余金币与时长分解的重复行；没有学到的强化、融合或道具不展示空行。窄屏仍为成绩和构筑双列，当前验证构筑完整显示，内容更多时只在干净正文区内滚动。补充正文边界不进入边框及窄屏最后一行可见断言；构建和相关回归通过。
