# 升级三选一美术接入

本轮完成升级界面的表现层升级。战斗、技能数值、随机抽取、商店、波次、首领、输入与游戏状态机源码保持不变。没有自动接入其他界面背景。

## 实现

- `src/upgrade-art.ts` 对全部 22 个真实 SkillId 提供编译期完整映射。URL 尊重 Vite BASE_URL。
- 普通、稀有、互斥进化分别使用现有青绿、紫色、金色卡底。类型来自 SkillDefinition.category；元素卡底按真实武器 ID 选择。
- 命中分裂区分火焰、荆棘；连锁弹射区分水、草。使用当前装备集合；无 RunBuild 的历史模式使用 fusionBase。兼容多武器同时展示对应两种插画。
- “施法节拍”没有专属插画，明确使用原始闪电图标。其他图片加载失败时也显示原图标；卡框失败时显示 CSS 羊皮纸卡底。图片完成加载不参与输入启用条件。
- 动态渲染名称、类别、当前/目标等级、核心效果、真实预览、稀有道具与进化代价；完整描述保留在无障碍描述中。新武器预览简写为“未装备 → 1级”。不修改 progression 中的计算或定义。
- 已获等级与下一等级用不同色条区分，避免把待选择等级显示为已拥有。
- 整张卡保持 button，保留 data-skill、data-offer、初始 disabled、全部事件委托。180毫秒防误触、offerVersion、连续升级、暂停和旋转处理仍由原 game.ts 实现。
- 标题横幅、卡框、宝石及插画为装饰图片；无文字烘焙。保留场景并叠加适度暗化/模糊。窄屏保留三列、代价和数值；不依靠裁掉文字适配。

## 素材

使用 skills、relics、upgrade/card-frames、upgrade/gem-* 与 common/forest-title-banner.png。沿用全部已分类 PNG，未改动原图、裁切成品或历史素材。原稿中少量低透明度残点和保守留白原样保留。

## 验证范围

生产构建 `npm run build`；针对性回归 `npx playwright test tests/upgrade-art.spec.ts tests/upgrades.spec.ts`，同时运行 Chromium 和 WebKit。

最终结果：构建通过，19 项通过、1 项既有条件跳过，无失败。构建仍提示 Three.js 分包超过500KB，未在本轮调整引擎打包策略。

覆盖全部 ID 与资源加载、元素变体、多武器组合、缺图与缺卡框回退、844×390及568×320文字分区、刘海安全区、真实暂停、连续升级、过期点击、触屏指针安全、旋转/后台恢复、满级与重新开始。WebKit 不支持 Chromium CDP 多点触控注入，该既有用例条件跳过。旧“MAX”断言同步到已有中文“满级”，其余原选卡回归测试保留。

截图：`artifacts/upgrade-art-chromium.png`、`artifacts/upgrade-art-small-chromium.png`；真实场景截图 `artifacts/upgrade-chromium.png`。本轮未运行全项目战斗/历史模式测试集。

## 插画比例与图文分区修正

根据实际截图反馈，新增23张仅供界面显示的紧凑插画副本，位于 `upgrade/illustrations`。脚本 `scripts/prepare-upgrade-illustrations.py` 用透明度大于2的像素检测主体边界，再扩展16像素保留周边光晕；副本不缩放、不修改裁切范围内颜色及透明度。仅移除远端近乎不可见残点所在的多余画布，原始素材完整保留，坐标记录在该目录 manifest.json。

标题上移至标题带，中部改为“弹性插画区＋效果行＋数值行”的网格布局；数值预览整体上移，短屏文字变多时自动让出插画空间。删除卡底重复的“点击选择”，避免与底部宝石重叠。补充全部22种卡牌的标题/插画、插画/效果边界断言，沿用其余选卡安全回归。

## 统一卡框修正（最新）

所有升级卡现统一使用 `upgrade/card-frames/common.png`，取代此前按元素/稀有度选择不同轮廓的卡框。标题带、插画区、文字区共用一套尺寸与安全区；元素与稀有度仍以动态标签、文字配色和宝石区分，原差异化卡框素材保留。插画限定在独立网格区域中，避免装饰和插画遮住标题或“武器强化”。增加普通强化与已装备火系武器强化、草系新武器同时出现的截图回归，验证同尺寸卡框和图片边界。当前针对美术层的10项回归均通过。
