## 实现

`src/creature-animation.ts` 提供数据配置与固定步进动画状态：动画名、方向、贴图、起始帧、帧数、FPS、循环、镜像、脚底锚点和时间。行走 8 FPS，依据实际速度在 0.55–1.3 倍范围调整；正面待机 3.5 FPS。非正面停止保留相应方向第一个站立帧，绝不强制朝正面。

方向采用**碰撞处理后的实际位移 / 固定时间步**，与相机的 right / up 基向量点乘，转换为屏幕速度后选最接近的八方向。屏幕下对应正面，上对应背面；左右和四个斜向按素材及水平镜像显示。没有把世界 X/Z 角度直接当作屏幕角度；测试覆盖不同相机方位和正确像素宽高比。

运动起止阈值为 0.12 / 0.07 世界单位/秒，方向边界滞回 7°。360° 模拟位移不量化，渲染朝向不回写位置、碰撞、速度或自动索敌。持续顶住障碍而实际位移归零时站立；攻击不会改变行走朝向。

扩展原 `PixelSpriteRenderer` 和 `PixelTextureCache`，没有另建角色渲染引擎。图集一次加载、共享纹理；每个实例的 SpriteMaterial 持有自己的帧 UV uniform，镜像只翻转该实例采样，不修改共享纹理 offset/repeat。NearestFilter、sRGB、关闭 mipmaps、alphaTest、深度测试沿用原像素显示。单元比例和脚点固定，移除动画模式下的整体上下起伏；保留原脚影、主控识别环和实际碰撞体。

`Game` 仅新增显示层调用：开始时启用并重置主控动画，固定逻辑步末提交实际位移，传入现有相机基向量，死亡时停止走路。动画不依赖 Date、独立计时器、CSS 动画或菜单渲染时间。暂停、选卡、后台不推进；死亡后站立并冻结，重开回到初始正面待机与零动画时间。

## 方向大小修复

用户反馈上下移动比左右大。新增回归在实际解码图集上测量可见主体高度，修复前各行最大高度为 220、220、186、220、220、219 像素，方向差异约 18%。根因是旧 320 像素宽单元的水平留白不足：侧面尾巴相对脚点向后延伸，脚本为塞入 150 像素半宽，额外缩小了整行侧面动画。

现将单元拓宽为 384×256，脚点保持居中且 y=240；各行统一按 220 像素目标高度归一化，横向放不下时明确报错，禁止再次靠缩小某个方向来容纳。运行配置同步新单元宽度。原图不改、不裁尾巴，脚底世界锚点、阴影、碰撞与移动逻辑不变。最新截图汇总和 GIF 已更新。

验证：先运行比例回归，实测 1.1828 的高度比导致失败；修复后比例、素材、方向播放、真实 GPU 显示、生命周期和融合专项共 **22 通过、0 失败、0 跳过**，`npm run build` 通过。本次仅复跑相关测试，前文全量测试为上次记录。修改前的脚本、配置和两个规范化图集及清单保存在 `D:/projects/MonsterBonk-Mobile-backups/direction-size-20261019-013759/`。
