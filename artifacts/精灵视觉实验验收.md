# 焰绒精灵视觉替换实验

日期：2026-10-18。分支：`feat/yanrong-sprite-trial`。改造前检查点：`c19fbef`（包含用户提供的新 PNG；未覆盖未提交源码）。

## 范围与回退

默认以 `public/assets/characters/yanrong-base.png` 显示初始焰绒，仍使用 Three.js 地图和原固定 45° 正交摄像机。源码只调整 `src/monster.ts`、`src/game.ts` 的显示接线，新增 `src/monster-sprite.ts`；地图、输入、碰撞、血量、战斗、技能、经验、升级、音效和画质模块均未修改，也没有新增依赖。

- 直接打开游戏：精灵模式。
- URL 加 `?character=3d`：使用原程序化模型，不请求 PNG。
- PNG 请求失败或无法处理：自动使用原模型，游戏可继续运行。
- `Monster.setVisual('sprite' | 'procedural')` 可切换显示，角色 root、位置和战斗实体不变。
- 原有头背尾插槽与器官实现完整保留在 3D 回退模型。本轮没有把器官拼贴到精灵，也没有增加器官、进化、技能或地图。

## 显示实现

- 主体使用 Three.js Sprite，直接挂在角色实体根节点，避开 3D 身体的朝向与缩放变换，始终朝向摄像机。
- 原图实际为 1254×1254 RGBA。加载时扫描透明留白，仅去掉不可见边框，保留整个可见轮廓及其比例；原 PNG 不改写。裁切后的轮廓宽高比约 0.9853。
- 纹理最长边限制为 1024，使用 sRGB、线性过滤和 mipmap。清理接近透明的导出杂点、将近乎实心的内部 alpha 归为不透明，并向透明边缘扩展邻近 RGB，减少暗边。
- `Sprite.center=(0.5,0)`，最底部脚掌锚在实体地面点上，静止高度偏移 0.025 世界单位。投影检查中，脚底与地面点的差值小于 1 CSS 像素。移动时最多约 0.055 世界单位的小幅起伏属于表现动画，不改变实体 Y。
- 地面阴影是固定在 Y=0.025 的柔和径向渐变平面，平面长宽为 2.1×1.35，形成软椭圆，没有实时阴影。
- 844×390 手机横屏的静止可见高度约 61 CSS 像素，568×320 约 56 像素；只调视觉尺寸，碰撞半径仍为原值。
- 普通移动有轻微起伏和倾斜，动态压缩幅度很小；冲刺时约 7.5% 的短暂纵向拉伸，静止时严格保持图片比例。
- 冲刺残影固定池最多 3 个 Sprite，全部共享角色纹理，使用独立透明度和已有位置对象，退出/重开会清理。受击仅改变显示颜色和透明度，不修改受伤或无敌时间。
- 主体启用 alpha test、depth test 和 depth write；透明像素不写深度。阴影先绘制、残影不写深度，其余由 Three.js 深度与透明排序处理，没有强制永远覆盖敌人或障碍。

## 测试证据

- `npm run build` 成功，包括 TypeScript 类型检查和 Vite 生产构建。
- `tests/sprite.spec.ts` 在 Chromium 和 WebKit 各运行 5 项，共 10 项专项测试通过：比例/地面对齐/短屏尺寸、模拟结果一致、真实 GPU 深度遮挡及透明角落、冲刺/受击/暂停/重开、图片缺失及手动回退。
- 遮挡测试实际读取 WebGL framebuffer：放在角色前面的不透明测试平面遮住角色；移到角色后面，角色正常显示；图片透明角落能看到平面。测试物件只存在于测试页面，生产地图未修改。
- 模拟一致性测试分别用精灵和原 3D 模型重置同一游戏，使用同一输入、同一敌人和同一随机值推进 90 个固定时间步，比较位置、计时、冷却和完整战斗快照，结果完全一致。
- `npm test` 全套回归结果：**102 通过、4 个 WebKit/CDP 用例按条件跳过、0 失败**。覆盖摇杆、多指冲刺、自动攻击与命中、经验收集、三选一升级、暂停/设置/重开、旋转和模拟后台事件，以及新增精灵测试。最终完整输出保存在 `sprite-test-output.txt`。
- `sprite-production-smoke.cjs` 在生产 dist 的 Chromium/WebKit 上通过自然击杀、移动冲刺、暂停/设置、重开、无 pageerror、无错误界面及生产诊断隔离检查；截图为 `sprite-production-menu.png`、`sprite-production-gameplay.png`，数据为 `sprite-production-smoke.json`。
- 对照检查点确认 `combat.ts`、`combat-view.ts`、`input.ts`、`progression.ts`、`world.ts`、`camera-25d.ts`、`style.css`、`ui.ts`、`quality.ts`、`audio.ts`、依赖与原始 PNG 无差异。

以上均为 Windows 桌面浏览器、手机横屏视口和触控模拟；没有 Android/iPhone 真机帧率、发热或功耗测试。

## 实验中可见的风格差异

1. 原图有细腻的毛发、渐变、火焰高光和预绘制光照，地图与敌人仍是平面色块和低多边形明暗，角色会显得更精细、饱和且突出。
2. 原图是固定四分之三朝向；向任意方向移动时都显示同一视图，没有背面或侧面动画。这会带来“画片滑动”的感觉，轻微起伏与倾斜只能减弱它。
3. 插画自身的视角与 45° 地图投影并不完全相同，四只脚的前后透视及预绘制光照不会随场景变化。脚底锚点与软阴影保证接地，但不能把单张图变成可旋转 3D 角色。

本轮保持上述差异供判断，没有重做地图。若决定采用这条路线，后续最值得补充的是少量方向帧或走路帧，而非全面重做场景。
