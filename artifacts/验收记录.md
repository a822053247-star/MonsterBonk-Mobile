# 第一阶段验收记录

验收日期：2026-10-17（北京时间）。

## 实现范围

在指定的空项目目录中创建了 TypeScript + Vite + Three.js 原型。已完成主菜单、程序化草原、原创角色、平滑跟随、摇杆移动、冲刺、固定生命值 HUD、暂停/继续、返回菜单、横竖屏处理、安全区域与后台暂停。

## 构建与测试

- `npm run build`：成功，包含严格 TypeScript 检查。
- `npm test`：13 项成功、1 项跳过。Chromium 7 项成功，Windows WebKit 6 项成功。WebKit 的双指注入因 CDP 仅适用于 Chromium 而跳过。
- Chromium 通过真实触摸事件注入验证双指：摇杆移动时第二指触发冲刺；单独抬起冲刺手指不影响摇杆；全部松手后归零。
- 两种浏览器验证：3D 画面确实渲染，主菜单/指南/开始、键盘、摇杆死区与归一化、拖出摇杆后松手、指针取消、冲刺冷却、暂停冻结、重开与资源稳定、旋转屏幕与后台/失焦事件处理。
- 暂停时停止 requestAnimationFrame，恢复后不补算后台经过的时间。
- 重开 3 次后几何体和纹理计数保持一致。
- 生产包实际打开无页面异常，HUD 和旋转提示正常，开发诊断接口没有进入生产包。
- 检查桌面 1280×720、横屏手机 844×390 和小屏 568×320 的菜单布局，并保存截图；额外模拟左右 44px、底部 21px 安全区域，菜单按钮与底部说明均在可用区域内。

## 渲染预算

自动化环境起始游戏视角：41 次 draw call、约 51,778 个三角形、15 个已上传几何体、1 张纹理。场景实例化、共享材质，无实时阴影、无后处理、无在线素材依赖。

Three.js 的独立生产 JS 约 540 KB（gzip 约 134 KB），Vite 会提示超过默认 500 KB 提醒阈值；这是体积提醒，构建成功。项目逻辑 JS 约 27 KB（gzip 约 10 KB）。

## 验证边界

未连接 Android 或 iPhone 真机。Windows Chromium/WebKit 自动化不能替代真机 Safari 的触摸、系统后台恢复、热量、耗电或帧率验收。visibility 测试通过可控事件输入验证处理逻辑。尚未测量中端手机实际 FPS。

当前没有战斗系统，生命值固定为 100。没有引入音频、外部模型或 Capacitor 平台工程。
