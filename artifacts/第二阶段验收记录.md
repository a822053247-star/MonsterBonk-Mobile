# MonsterBonk Mobile 第二阶段验收

日期：2026-10-17（北京时间）。项目在原目录升级到 0.2.0，没有重建项目，没有新增 npm 运行依赖。

## 已交付

- 保留原地图、芽噜模型与动画、第三人称平滑跟随、Pointer Events 多指摇杆、冲刺与后台暂停。
- 三种原创敌人：普通赤团、快速疾芽、坦克岩甲。随机环形出生、预警、追逐、分离、绕障、地图边界与远距回收。
- 自动选择射程内无遮挡的最近有效敌人，发射可见魔法弹；实际线段碰撞，命中扣血、闪白、击退、受损血条与碎光。
- 接触伤害、0.85 秒全局受伤无敌、角色闪烁、屏幕红边、血量归零结算、失败后重开。
- 死亡经验球、近距自动吸附、击败与经验统计；满池时合并经验而不丢失。
- 暂停直接重开、失败后重开、返回菜单都重置完整战斗状态。
- 48 敌人 / 24 魔法弹 / 96 经验球 / 48 组特效的固定池，实例化显示，共享几何体和材质。
- 经验目前只累计，不包含升级选择或数值强化。

## 文件

- `src/combat.ts`：不依赖 DOM/GPU 的战斗计算和固定对象池。
- `src/combat-view.ts`：敌人、预警、弹体、血条、经验球和特效的实例化显示。
- `src/game.ts`：接入原固定步长、HUD、伤害和结算重开。
- `src/ui.ts` / `src/style.css`：更新 HUD、指南、结果页及小屏安全区域。
- `tests/combat-model.spec.ts`：8 项战斗模拟测试。
- `tests/game.spec.ts`：移动/暂停回归，增加双指移动中射击、经验拾取、HUD 和完整重开清理。
- `tests/gameover.spec.ts`：隔离测试页面使用真实 Game/UI 模块触发致死接触，验证停止游戏循环、结果面板与失败后重开。测试入口不进入生产包。

## 执行结果

1. `npm run build` 成功：严格 TypeScript 检查与 Vite 生产打包均通过。
2. 完整 `npm test`：**33 项通过、1 项跳过**。Chromium 双指真实事件注入成功；WebKit 的同一 CDP 双指项因工具不支持跳过。
3. 调整小屏结果页后，再运行 `npm test -- tests/gameover.spec.ts`：Chromium / WebKit **2 项通过**，覆盖 568×320 视口加左右 44px、底部 21px 安全区域，结果卡片完整显示。
4. 单独复验两种浏览器的完整战斗流程：2 项通过，并额外复验 WebKit 1 项通过。Windows WebKit 的截图合成偶尔遗漏整个 WebGL 画布，但进一步读取原始 WebGL 帧缓冲得到了正确的角色/草地像素，上下文未丢失，也无警告或错误。独立检查的战斗和恢复截图正常，分别保留在 `combat-webkit.png` 与 `webkit-combat-after-pause.png`；原始画布输出为 `webkit-framebuffer.png`。常规自动战斗截图使用 Chromium，WebKit 仍执行全部功能断言。不必要的弹窗模糊已移除。这不能替代 iPhone 真机验证。
5. 生产包通过 `vite preview` 实际打开：自动产生击败计数，无页面异常；重开后血量 100、击败 0、经验 0。生产包没有暴露开发诊断接口。记录见 `combat-production-smoke.json`。

测试覆盖最近合适目标过滤、三种追逐速度与血量差异、伤害/闪白/死亡、经验只收集一次、伤害无敌与致死冻结、高速弹线段命中、出生距离/地图边界/避障、30/60/120 Hz 帧调度下固定步结果一致、3 分钟战斗模拟、满池经验合并、池上限、重置清理，以及原有移动、触控、旋转与后台流程。

## 体积和设备边界

项目逻辑 JS 约 41 KB（gzip 约 15 KB）；Three.js 独立包约 542 KB（gzip 约 135 KB），Vite 默认 500 KB 体积提醒仍存在，不影响构建完成。没有实时阴影或昂贵后处理，没有外部模型/贴图/字体请求。

未连接 Android 或 iPhone 真机。Windows Chromium/WebKit 自动化不能确认手机实测 FPS、发热、耗电、真实系统后台或低内存恢复；真实手机清单在项目 `README.md` 的「请在真实手机上测试」一节。
